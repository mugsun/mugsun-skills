# mugsun-doc：文档站同步

## 触发词

更新文档、补文档、文档站、docs.mugsun.com、英文文档、同步文档、update docs。

## 必问参数

1. 改动来源：对应哪个仓库的哪次改动（提交 SHA 或分支）。
2. 影响范围：新功能、行为变化、配置改名、接口变化，还是只是纠错。
3. 页面位置：改哪一页，或新页面放在哪个章节下。

## 默认值

- 中文和英文页面在同一次提交里一起改，不留单边。
- 文风：短句、说事实，不写空泛的形容词，不写「里程碑」「全面升级」之类的话。
- 配置项、类名、命令都写成代码格式，并和代码里的实际名字一致。
- 截图只在文字说不清时才加。
- 中文每段不超过 80 字，不硬换行，不用加粗的小标签。
- 直接在 main 上提交，不开 PR。
- 文档改动 CI 绿即可进 main；安全相关文档除外，先给安全官看。
- 对应代码进 main 之后才推文档。
- 只用普通推送，禁止 force、rebase、`--no-verify`；main 已前移时先 `git merge origin/main` 再推。

## 不适用于

- 各仓库自己的 README、CHANGELOG、AGENTS.md（用 mugsun-commit 或直接改该仓）。
- 营销页和官网首页。
- 没有对应代码依据的「规划中」功能：不要写成已有功能。

## 步骤

1. 读改动对应的代码或提交，列出用户可见的变化。
2. 在文档站源码里找到相关页面（中文页和英文页各一份），没有就按章节结构新建两份。
3. 先改中文，再按中文改英文；两边的标题、小节、代码块、配置表一一对应。
4. 每个配置项、类名、命令都回到代码里核对一遍名字和默认值。
5. 本地检查：构建只在指定的构建机上运行，重任务通过构建机的重任务队列排队、一次只跑一个。在构建机上运行 `pnpm docs:build`、`scripts/check-doc-width.py`、`scripts/check-changelog.py`，确认链接和侧边栏没有断、段宽和 CHANGELOG 合规。
6. 按 Conventional Commits 提交，例如 `docs(boot): 补充数据权限配置说明`。
7. 普通推送到 main 后，用 `gh run list --commit <sha>` 确认 Docs CI、Security scan、Deploy docs 三项都绿。

## 产出

- 中英两份页面的改动，在同一个提交里。
- 一份核对清单：每个写进文档的名字和它在代码里的位置。
